geha/MCP_server — stdio MCP interface

Nine Stages, One MCP Server

server.py wraps nine deterministic insurance-processing simulators behind seven MCP tools, talking JSON over stdio — no HTTP listener, no LLM, no database. Every call in is a small JSON argument object; every result out is a structured JSON payload written by flow_service.py. Ask for one stage and its prerequisites run automatically: run_flow({"flow_id":"04"}) quietly runs 01 first, because 04 reads what 01 wrote.

One call, resolved dependencies

REQUEST — client → server
{
  "name": "run_flow",
  "arguments": { "flow_id": "04" }
}

09Compliance & Regulatory

needs 01–08 — checks their evidence files exist

run_flow({"flow_id":"09"}) — runs all nine, in dependency order

{
  "flow": "09_compliance",
  "execution_status": "completed",
  "summary": {
    "evidence_files_expected": 9,
    "evidence_files_present": 8,
    "evidence_files_missing": 1
  },
  "compliance_verified": false,
  "warnings": [
    "Evidence checks primarily test file existence.",
    "HIPAA check is an always-pass placeholder."
  ],
  "outputs": ["compliance_register.json", "compliance_events.json"]
}

None of this is a real determination. execution_status: "completed" means the script ran to the point of writing a response — not that any authorization, payment, or compliance check reflects reality. Stage 09's own compliance_verified: false is the server telling you that directly: it counts whether evidence files exist, not whether GEHA is actually in compliance.
