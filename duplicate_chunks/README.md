# Duplicate Chunks

A small web app for finding, measuring and verifying duplicate chunks in the
GEHA `crawl_dir` corpus. Built with React, Vite, TypeScript and Tailwind.
Shared state lives in a Zustand store (no prop drilling), and Zod validates
every data file the app loads.

## Run it

```bash
cd /Users/dc/duplicate_chunks
npm install
npm start          # analyze crawl_dir, then serve on http://localhost:5180
```

Or in two steps:

```bash
npm run analyze    # scan crawl_dir and write public/data/
npm run dev        # serve the app
```

After re-running `npm run analyze`, press **Reload** in the app header.

### Analyzer options

`scripts/analyze.mjs` has no dependencies and runs on any Node 18+.

```bash
node scripts/analyze.mjs --crawl-dir /Users/dc/geha/crawl_dir \
  --near 0.7 --containment 0.9 --shingle 3 --min-tokens 8
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--crawl-dir` | `/Users/dc/geha/crawl_dir` (or `$CRAWL_DIR`) | Corpus root |
| `--near` | `0.7` | Jaccard over word 3-grams for a near duplicate |
| `--containment` | `0.9` | Share of the smaller chunk found in the larger one |
| `--shingle` | `3` | Words per shingle |
| `--min-tokens` | `8` | Shorter chunks are only checked for exact matches |
| `--out` | `public/data` | Where the report is written |

## What it does

**Processed or not.** Every PDF under `crawl_dir/raw/<family>/` is a document.
Its status follows the same rule as `crawl_dir/src/consumer_paths.py`:

- **Reviewed**: a promoted version exists under `reviewed/`.
- **Processed**: a candidate run passed structural QC (`needs_visual_review` or
  `passed`, no structural errors) and has `candidate/chunks.jsonl`. The newest
  such run is used.
- **Failed**: runs exist, but none is usable.
- **Not processed**: no run yet.

The Coverage tab also shows which pages produced no chunk and how many pages
have passed visual verification. Runs whose source PDF is missing from `raw/`
are listed too.

**Duplicates.** Only the selected run of each document is analyzed, so
re-ingesting the same PDF is not counted as duplication.

1. **Exact**: identical after lowercasing and stripping whitespace, markdown
   and HTML tags.
2. **Near**: MinHash (128 permutations, 64 LSH bands) proposes candidate pairs;
   each is confirmed with true Jaccard over 3-word shingles.
3. **Containment**: the smaller chunk sits almost entirely inside the larger
   one (boilerplate embedded in a longer section).

Pairs whose figures differ (dollar amounts, percentages, years, ratings like
"2A") are flagged as **look-alikes**: similar wording about a different amount
or plan year is a different fact, not a duplicate. Look-alikes stay in the
explorer for review but are not counted as redundant. Among the remaining
pairs, each connected group keeps its longest chunk as canonical and counts
the rest as redundant.

## The app

- **Dashboard**: share of redundant chunks and text, breakdown by duplicate
  type, scope and family, coverage summary, most redundant documents and the
  largest groups. Bars are clickable and open the explorer filtered.
- **Coverage**: every document with its status, selected run, page coverage,
  visual verification and redundancy. Expand a row for details.
- **Explorer**, three views:
  - *Duplicate groups*: filter by type, scope, family, review state and
    differing figures; pick any two members as A and B.
  - *Side-by-side compare*: word-level diff, similarity scores recomputed in
    the browser, figures present on only one side, and a verdict
    (duplicate / not duplicate / unsure). Keyboard: `1` `2` `3` for verdicts,
    `←` `→` to step, `n` for the next unreviewed pair, `d` to toggle the diff.
  - *Document*: all chunks of one document in order, marked canonical or
    redundant; select a chunk to see every other place its text appears.

Verdicts are saved in the browser and can be exported or imported as JSON.

## Layout

```
scripts/analyze.mjs        corpus scan and duplicate detection
src/lib/schema.ts          Zod schemas for report.json and per-document chunks
src/store/useStore.ts      Zustand store: data, selection, filters, verdicts
src/hooks/                 chunk loading and the filtered review queue
src/components/            Dashboard, Coverage, Explorer views
public/data/               generated by the analyzer (git-ignored)
```
