From Weather Tool to Claim Review

Every graph below is built from the same four LangGraph primitives: a StateGraph, add_node, add_edge, and add_conditional_edges. What changes between them is what the state holds and what happens at the branch — not the machinery. RAG_demo/rag.py is the simplest graph in this repo: two nodes, no branching. The canonical LangGraph tutorial graph — an agent deciding whether to call a weather tool — adds a conditional edge and a loop. langgraph_demo/demo.py uses that exact same conditional-edge shape, but the thing it's waiting on is a person, not a tool result.

1. The simplest graph in this repo

The next graph isn't from this repo. It's the shape almost every LangGraph tutorial starts with: an agent deciding whether to call a tool. It's here because langgraph_demo/demo.py uses the exact same conditional-edge pattern — just waiting on a reviewer instead of a tool result.

2. The pattern: an agent that can loop

Swap the tool for a person. langgraph_demo/demo.py keeps the conditional edge and the pause-and-resume shape, but the thing being waited on is a reviewer's decision, and the pause survives a process restart because the graph is checkpointed.

3. The GEHA claim-review workflow

The two additions on top of the toy example: interrupt(), which pauses a node mid-run and hands control to whatever's outside the graph, and a checkpointer, which makes that pause durable across process restarts. Everything else — nodes, edges, one conditional branch, a shared state dict — is the same graph you'd draw for the weather tool.
